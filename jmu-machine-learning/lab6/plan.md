# 实验六 - 卷积神经网络

## 一、实验思路
- 数据集：`MNIST`，自带手写数字图像，最适合做入门 CNN 分类实验。
- 框架：优先使用 `PyTorch`，便于写代码和做对比实验。
- 环境：先在 `Windows` 原生环境跑通，再尝试 `GPU` 加速训练，最后对比 `CPU vs GPU` 的训练时间和效果。

## 二、实验目标
- 实现一个基础 CNN 分类器。
- 修改网络参数配置，比较不同配置下的效果。
- 输出训练曲线、测试准确率、损失变化和对比表格。

## 三、对比方案
- 方案 1：基础 CNN + 默认参数。
- 方案 2：调整卷积核大小。
- 方案 3：调整学习率。
- 方案 4：加入 `Dropout` 或增加卷积层数。
- 方案 5：`CPU` 训练与 `GPU` 训练对比。

## 五、文件职责
- `exp1/`：模型与超参数对比实验代码。
- `exp2/`：CPU/GPU 性能对比代码。
- `exp3/`：基于训练结果的 PyQt 交互式数字识别 GUI。
- `results/`：所有实验的最终输出目录，图表、md、csv 都放这里，方便 GitHub/Gitee 直接阅读。
- `report/`：整份实验报告正文，最后再导出 PDF。
- `原始资料/`：老师提供的原始内容，保留不动，只用来参考，不往里面写实验输出。

## 六、推荐执行顺序
1. 先写 `01_cnn_base.py`，确认 MNIST 能正常训练。
2. 再补参数对比脚本，跑 3 到 4 组实验。
3. 最后做 `CPU vs GPU` 时间统计。
4. 再做 `PyQt GUI`，加载训练好的模型进行手写数字识别。
5. 汇总结果，生成 Markdown 分析报告。

## 六点五、脚本编写约定
- 后续 `exp2`、`exp3` 也保持和 `exp1` 一样的风格：运行时要有明显的进度输出，避免看起来像卡死。
- 训练类脚本至少输出：当前实验名、设备信息、参数配置、每个 epoch 的准确率和损失、总耗时。
- 如果环境里装了 `tqdm`，就显示批次进度条；如果没装，也要保留普通文本日志。
- 所有实验结果统一输出到 `results/`，不要写入老师提供的原始资料目录。

## 七、exp1 文件说明
- `00_env_check.py`
  - 作用：先检查电脑环境是不是准备好了。
  - 它会做的事：打印 Python 版本、PyTorch 版本、CUDA 版本，还会看 GPU 能不能被识别。
  - 为什么要先跑它：如果这里都不通，后面的训练脚本就没法跑。
  - 运行后你会看到：一块带框的输出，里面会写“GPU 可用”或者“仅 CPU 模式”。

- `common.py`
  - 作用：公共工具箱，所有训练脚本都要用它。
  - 里面通常放什么：
    - CNN 网络结构
    - 数据集加载方法
    - 训练一轮的方法
    - 测试准确率的方法
    - 保存模型和保存 CSV 结果的方法
  - 为什么要单独放：这样 `01`、`02`、`03` 不用重复写一大堆代码。

- `01_cnn_base.py`
  - 作用：先训练一个最基础的 CNN 模型。
  - 它做的事：用默认参数训练 MNIST，看看这个模型能不能正常识别手写数字。
  - 你可以把它理解成：整套实验的“起跑线”。
  - 运行后你会看到：训练结果、测试准确率，以及保存好的模型文件和 metrics 表格。

- `02_kernel_compare.py`
  - 作用：比较不同卷积核大小的效果。
  - 它做的事：比如分别用 `3x3` 和 `5x5` 的卷积核训练，看看谁更好。
  - 为什么要做：卷积核大小会影响模型看图像的方式，也会影响准确率和训练速度。
  - 你可以把它理解成：在问“模型用小眼睛看图，还是用大眼睛看图更好？”
  - 运行后你会得到：两组结果，方便后面写对比分析。

- `03_lr_compare.py`
  - 作用：比较不同学习率的效果。
  - 它做的事：比如用 `1e-3` 和 `5e-4` 分别训练，看看收敛速度和准确率有什么区别。
  - 为什么要做：学习率太大可能学不稳，太小可能学得慢。
  - 你可以把它理解成：测试“模型学习快一点好，还是慢一点更稳”。
  - 运行后你会得到：两组训练结果，用来写实验分析。

- `04_analysis.py`
  - 作用：把前面几组实验结果整理成一篇 `Markdown` 报告。
  - 它做的事：读取 `csv` 文件，汇总准确率、损失、训练时间，再自动生成分析文字。
  - 为什么要做：这样不用手工一个个复制结果，写报告会快很多。
  - 运行后你会看到：一个完整的 `md` 文件，里面可以直接拿去改成实验报告正文。

## 八、后续 exp2 / exp3 的分析脚本思路
- `09_analysis.py`
  - 作用：整理 `CPU` 和 `GPU` 训练对比结果。
  - 它做的事：读训练时间、准确率、损失，生成一份性能对比 `md`。
  - 重点：突出 `GPU` 在训练速度上的优势。

- `08_batch_compare.py`
  - 作用：再补一组批量大小对比。
  - 它做的事：比如用不同 `batch size` 跑同样的训练，看看速度和准确率的差别。
  - 重点：解释为什么有的配置训练更快、有的更稳。

- `09_analysis.py`
  - 作用：把 `CPU / GPU / batch size` 的结果一起整理成对比 `md`。
  - 它做的事：汇总训练时间和准确率，最后输出一份更完整的性能分析。

- `13_prediction_test.py`
  - 作用：单独测试 GUI 的识别效果。
  - 它做的事：加载模型后，对几张手写数字图片做预测，方便截图放到报告里。
  - 重点：证明 GUI 不只是能打开，还真的能识别数字。

- `14_analysis.py`
  - 作用：整理 `PyQt` 数字识别界面的说明和测试结果。
  - 它做的事：记录 GUI 的使用方式、加载模型方式、识别效果示例。
  - 重点：说明这个界面怎么和前面的训练模型配合起来用。
